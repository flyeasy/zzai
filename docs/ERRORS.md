# 失败文案表（错误码 → 用户看到什么 → 下一步 → 能不能重试）

原则：每个失败都要有**名字**和**下一步动作**；能用一句话说清的，不说两句；能重试的，明确说从哪儿重试。

| 错误码 | 什么时候出现 | 用户看到的文案（要点） | 下一步 / 可重试 |
|---|---|---|---|
| `no_audio` | 录音里完全收不到声音（设备静音、选错设备） | 「麦克风『X』没有收到声音：检查它是否被静音，或换一个输入设备」 | 检查系统「声音 → 输入」；不可重试（没声音可重试也没用） |
| `too_quiet` | 有声音但峰值 <2%（离得远、输入音量低、外放回声） | 「声音太小了（峰值 N%）：靠近麦克风一点，或把输入音量调高。这次没有上屏」 | 调音量/靠近；本次不落盘 |
| `too_short` | 按住不到 `min_record_ms`（默认 400ms） | 「按住 Nms 太短了（至少 400ms）：按住说完整句再松开」 | 重说即可；双击热键可取回上一次结果 |
| `empty_result` | 有声音但识别不出内容 | 「声音太小或不清楚：靠近麦克风再说一次，或检查是否选错了输入设备」 | 重说；模型没装时会另报 `model_missing` |
| `asr_failed` | 识别引擎报错 | 「识别失败：…。音频已保留 24 小时，可从菜单重试（历史 id）」 | 菜单「重试上次失败的识别」⌘R |
| 同上 + 隐私模式 | 隐私模式下的识别失败 | 「识别失败：…。隐私模式下音频没落盘，本次运行内可从菜单重试」 | 仅本次运行内可重试 |
| `partial_result`（不是错误） | 长听写里有个别段失败 | 「N 段里有 M 段没识别成功，已保留成功部分」+ 浮层「⌘R 重试」 | 菜单「重识别失败的段」逐段重试；结果只进剪贴板 |
| `segment_*` | 单段重试相关（`segment_not_found` / `segment_empty` / `segment_busy` / `segment_retry_failed`） | 「第 N 段没有可重试的音频」「这一段还是没识别出内容」等 | 换段重试或重新录 |
| `submit_failed` / `submit_undelivered` / `submit_unknown` | 上屏请求失败/没送到/结果不明 | 「上屏结果未知（任务 X），文字已保存，可从菜单复制」 | **绝不二次注入**；菜单「复制上次结果」⌘C |
| `polish_failed` | 润色请求失败（网络/Key/超时） | 「润色没成功，已用原文：…」 | 原文照常上屏；下次检查 Key/网络 |
| `lan_no_token` | 局域网接口拒绝启动 | 开了「允许其它设备访问」但没设 token，等于同一网段谁都能用 | 设一个 token，或关掉「允许局域网」只给本机用 | 改完重启 | 否 |
| `lan_failed` | 局域网听写接口起不来 | 端口被别的程序占了，或 `allow_lan` 下没权限监听；换端口或关掉这个功能 | 改端口后重启 | 否 |
| `mic_unplugged` | 录音中设备被拔掉/被独占 | 「麦克风中断了（可能被拔掉或被其他应用占用）：已保留中断前录到的内容」 | 自动把已录部分送去识别 |
| `mic_unavailable` | 打不开麦克风 | 「打不开麦克风：…」并列出可用设备名 | 设置 → 音频 换设备；不静默回退 |
| `model_missing` | 引擎模型没装（或路径不对） | 「模型未安装：…」 | 设置 → 引擎「下载 247MB」，或首次启动的下载弹窗 |
| `bad_engine` / `engine_switch_failed` | 引擎名非法/切换时建引擎失败 | 「未知引擎：…」「切换引擎失败：…」 | 保持在旧引擎继续工作 |
| `decode_busy` / `retry_unavailable` | 解码线程正忙 / 没法重试（没有失败音频或正在解码） | 「正在识别，稍等」/「现在没有可重试的识别」 | 等当前这轮结束再点重试 |
| `engine_ready`（不是错误） | 后台重建引擎完成（切换引擎后） | 菜单/日志「引擎已就绪：qwen3」 | 无需动作 |
| `segment_spawn` | 起重识别线程失败（系统资源紧张） | 「启动重识别失败，请稍后再试」 | 稍后重试；持续出现看 `--diagnose` |
| `busy` | 上一轮还在录音/识别时又触发 | 「正在录音或识别，稍后再重试」 | 等当前这轮结束 |
| `cancel_rejected` | 上屏阶段（Inserting）请求取消 | 「已经开始上屏，取消不了这次」 | 等它贴完，必要时手动撤销 |
| `stale_submit` | 迟到的提交（上一轮的任务号） | 文案交给 shell，按任务号忽略 | 无需动作 |
| `worker_panic` | core 线程 panic（被 `catch_unwind` 抓住） | 「内部控制线程出错了：已停用当前实例，请重开 Eryu」 | 重开应用；诊断信息在 `--diagnose` |
| `config_save_failed` | 写 config/热词/档位失败 | 「保存失败：…（已保留原配置）」 | 检查文件权限；旧配置继续生效 |
| `voice_all_skipped`（notice） | 「只录我的声音」把整段都滤掉了 | 「这段话都不像你的声音，已跳过…」 | 关掉声纹门控，或重新注册声纹 |
| `voice_skipped`（notice） | 部分段被声纹滤掉 | 「声纹过滤掉 N/M 段」；≥1/3 时整段重跑不过滤 | 无需动作（保底已生效） |
| `record_limit`（notice） | 到录音上限（默认 120s） | 「到 N 秒上限了，已自动结束并开始识别」 | 正常上屏；想更长去设置里调 |
| `skipped`（音源锁定） | 插话段被跳过 | 菜单/日志记录「锁定第 1 段；留下 2 段、跳过 1 段」 | 设置里可关 |

## 文案规范

- 说**发生了什么** + **为什么** + **你该做什么**，三句以内。
- 不出现「错误 500」「失败」这种只有结论没有动作的话。
- 能用用户语言描述的位置，就不写内部路径（路径只在诊断页出现）。
- 结果永远不静默丢：识别失败会保留音频 24 小时（隐私模式除外），上屏未知会保留待复制文本。
