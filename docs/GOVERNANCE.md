# 工程治理：版本 / 需求 / 进展（自 2026-11-20 起强制执行）

> 目的：让每次会话都能接着上一个人的成果往下走，不跑飞、不重复、不丢需求。
> 一句话规则：**先改文档，再改代码；代码与环境改动在同一提交里附文档。**

## 1. 文档的优先级

| 优先级 | 文档 | 作用 | 谁能改 |
|---|---|---|---|
| 1 | `DESIGN.md` | 唯一设计权威。架构、流程、参数、里程碑 | 只在「需求已确认」时改，且必须写清版本号与决策编号 |
| 2 | `docs/REQUIREMENTS.md` | 需求登记簿（R-xxx），一条需求一行事实 | 新增/修改需求时改 |
| 3 | `docs/DECISIONS.md` | 决策记录（D-xxx），含「为什么否决另一条路」 | 每次做技术选型就写 |
| 4 | `docs/ISSUES.md` | 未解决问题（I-xxx），现象/根因/复现/现状 | 发现即写，修好标「已修」 |
| 5 | `docs/PROGRESS.md` | 阶段台账，一行一件事，含验证方式 | 每完成一件事就加一行 |
| 6 | `CHANGELOG.md` | 用户可读的版本变更 | 每次冻结版本 |

冲突时以编号大的为准，但**必须回头改掉旧文档**，不允许两份说法并存。

## 2. 编号规则

- 需求 `R-1xx`：0.8 起的新需求从 **R-101** 开始，旧号段不再复用。
- 决策 `D-1xx`：同上，从 **D-101** 开始。
- 问题 `I-1xx`：同上，从 **I-101** 开始。
- 阶段台账：`0.8.1`、`0.8.2`……每个可交付的小步一行。
- 提交信息：`<范围>: <做了什么>`，范围用 `win` / `mac` / `core` / `docs`。

## 3. 需求状态机

```
提案 → 已确认 → 开发中 → 待验收 → 已完成 / 已否决
```

- **提案**：只有「用户原话 + 出处」才能立项，写在 BACKLOG 里。
- **已确认**：写进 `REQUIREMENTS.md`，同时更新 `DESIGN.md` 对应章节（这是「落回设计」）。
- **待验收**：必须给出可重复的验收命令或截图路径，否则不算完成。
- **已否决**：在 BACKLOG 标 `✗ 否决 + 理由 + 日期`，不删除（防止反复提）。

## 4. 完成定义（DoD）

一件事只有同时满足下面 4 条才能标「完成」：

1. 代码合入（`git commit`，工作区干净）；
2. 有自动化或可复现的验证（`cargo test` / `scripts/smoke.sh` / `--xxx-test` / VM 截图）；
3. 文档落盘：DESIGN（若涉及行为/参数）、REQUIREMENTS（若新增需求）、DECISIONS（若做选型）、ISSUES（若留下已知边界）、PROGRESS（一行台账）；
4. 版本相关：改动进入 `CHANGELOG.md` 的「未发布」段落。

## 5. 版本节奏

- 每次冻结：`packaging/Info.plist` 版本号 + `CHANGELOG` 段落 + `scripts/dist.sh` 闸门全绿 + `git tag vX.Y.Z` + 备份（见 `docs/BACKUP.md`）。
- Windows 与 macOS 各自出离线包（`Eryu-<ver>.zip` / `Eryu-Windows-<Wn>.zip`），sha256 写进 `docs/WINDOWS.md` 与邮件正文。
- **不允许**在没有验收记录的情况下自称「已对齐 / 已支持」。

## 6. 防「跑飞」的边界

- 一次会话只推一个版本号内的范围；跨版本的念想写进 BACKLOG，不动手。
- 改 UI 必须附截图（macOS：`screencapture -x -R`；Windows：VM 里 `CopyFromScreen`），截图放 `docs/`。
- 改 core 行为必须附测试或 `--decode-wav` / `--simulate` 的实测输出。
- 失败/未知一律写 ISSUES，不许「口头已知」。
- 与用户既有偏好在冲突时停下来问，不要自行扩大范围。

## 7. 会话交接协议

新会话开工前必读顺序：

1. `docs/KICKOFF-0.8.md`（本次交接单）
2. `DESIGN.md`（重点 §3 架构、§4 流程、§5 里程碑）
3. `docs/REQUIREMENTS.md` + `docs/BACKLOG-0.8.md`（要做什么）
4. `docs/ISSUES.md` 里状态为「未解决」的条目（别踩同一个坑）
5. `docs/PROGRESS.md` 最后 20 行（上一段做到哪）

会话结束前必须做：更新 PROGRESS 一行 + 提交 + 在 `docs/KICKOFF-*.md` 末尾追加「本轮结束状态」。
