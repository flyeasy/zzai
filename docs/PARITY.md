# macOS 与 Windows 对齐情况（2026-11-20 更新）

回答两个问题：**视觉和功能对齐了吗？不同分辨率/缩放能自适应吗？**

结论先说：
- **核心链路（按住说话 → 浮层 → 流式文本 → 上屏）两边一致**，都在真机上跑通过。
- **视觉尺寸按同一套数值实现**（胶囊 40、圆角=高/2、电平条 3.5/2.5、正文 14、下划线 15、提示 10、宽度 190–420、24 台阶），差异只剩「图标用什么画」。
- **DPI/分辨率是自适应的**：所有尺寸按 `dpi/96` 缩放，位置夹到光标所在显示器的工作区；100% / 150% / 200% 三档截图与 6 个几何单测都过。
- **设置窗口已搬到七页**（通用/引擎/音频/热词/历史/润色/诊断）；2026-11-20 晚补齐「选区改写 / 注入后校验 / 暂停媒体 / 档位快捷键槽 / 重识别失败段 / 首次引导 / 模型镜像」，仍未搬的只剩「待复制卡片」这一项（Windows 上粘贴校验失败时目前只弹提示、不建卡片）。

## 三、分辨率与缩放

实现方式：
- 所有尺寸写成 **pt 常量**（与 macOS 同值），渲染前乘 `dpi/96`；
- DPI 取**光标所在显示器**（`MonitorFromPoint` + `GetDpiForMonitor`），不是在进程启动时算一次——所以把窗口拖到另一块不同缩放的屏幕、下一次录音就按新比例画；
- 位置夹到**该显示器的工作区**（`rcWork`，自动排除任务栏），支持左副屏负坐标；
- 进程启动即声明 `PER_MONITOR_AWARE_V2`（I-066），否则系统会帮我们「虚拟化」坐标导致浮层错位。

实测（真机 2560×1440）：

| 缩放 | 浮层像素 | 换算回 pt | 结论 |
|---|---|---|---|
| 100% | 240×56 | 240×56 | ✅ |
| 150% | 396×84 | 264×56 | ✅ 宽高同步放大，文字/条/圆角一起放大，不是只放大画布 |
| 200% | 528×112 | 264×56 | ✅ |
| 真实 DPI | 240×56 | 240×56 | ✅（该机 100%） |

几何单测（`shell-win/src/overlay.rs::tests`，`cargo test` 在 Windows 上跑，11 项全绿）覆盖：光标贴底翻上方、右边缘夹紧、150% 下边距同步放大、1280×720 小屏完整可见、左副屏负坐标、无光标时居中并让开任务栏。

**还没验证**：真实 150%/200% 缩放屏（这台机器只有 100%），目前是用 `--overlay-scale 150/200` 强制缩放验证渲染；改缩放比例需要重启会话，远程做会打断测试环境，等有第二台机器或用 4K 屏时补。

## 四、结论

- 视觉：核心指标逐项同值，唯一实质差异是「档位图标」——macOS 用 SF Symbol，Windows 用汉字徽标（Windows 没有对应的符号字体，硬凑反而不像）。
- 功能：**输入链路完全对齐**；配置界面 W3 已搬五页（通用/引擎/音频/热词/诊断），历史统计与润色档两页待 W4。
- 分辨率：自适应成立，含多屏与 DPI 变化路径；真实高 DPI 屏待补一次实测。
