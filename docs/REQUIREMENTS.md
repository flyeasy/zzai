## R-015 隐私模式

开启后不写转写历史、不落盘失败音频、浮层不显示识别文本；上屏与热键不受影响；失败音频在本次运行内仍可 ⌘R 重试。
设置页「通用 → 隐私」可切换；默认关闭。

## R-016 选区指令改写

在任意应用里选中一段文字 → 菜单「选区改写…」（⌘E）→ 浮层选指令（润色/正式/精炼/英文/总结）→
文本就地替换。替换优先用辅助功能写回，失败退回粘贴；结果拿不到时留在剪贴板。
需要「辅助功能」权限；需要润色服务已配置（共用设置页「润色」里的地址与 Key）。

## R-017 热词自动学习

上屏成功后观察该输入框最多 15 秒；用户把某个词改掉时，把「原词 → 新词」放进设置页「热词 → 自动学到的改法」，
由用户点「采纳」写入 `hotwords.toml`。隐私模式下不观察。

## R-018 录音时暂停音乐

可选（默认关）：按住说话时暂停正在播放的 Music / Spotify，松手后恢复；只恢复本次自己暂停的播放器。

## R-019 上屏方式可选、可按应用覆盖

设置 → 通用 → 上屏方式：粘贴（默认）/ 逐字打字；可对单个应用覆盖（应用名包含匹配，大小写不敏感）。
打字方式在安全输入状态下明确失败并提示手动复制，不静默丢弃。

## R-020 注入后校验

粘贴后 350ms 读一次焦点控件文本：包含上屏内容算成功；明显缺失时提示并且不自动重贴（文本可从菜单取回）。
读不到控件的应用按成功处理，避免误报。

## R-021 应用内模型下载

设置 → 引擎：未安装的模型显示「下载 XXXMB」按钮，点了走系统 curl 拉官方发布包、tar 解包、进度条百分比，
完成后可直接切换。同一时刻只允许一个下载；已安装的模型显示体积与「使用中/切换」。

## R-022 「松手→出字」延迟要看得见

菜单里常驻显示「上次：松手→出字 Nms」，便于用户和我们判断是否变慢；对应 DESIGN §11 的验收口径 p95 ≤ 1.5s。

## R-023 长听写的边界要说清楚

录音到「单次上限」（默认 120s，可调 30–300s）时自动结束并提示「到 N 秒上限了，已开始识别」；绝不悄悄截掉开头。

## R-024 背景降噪要能关、要诚实

采集侧 RNNoise 默认开（仅 48kHz 麦克风），设置页可关；文案如实写明「稳态噪声有效，强噪声下有好有坏」，不承诺「任何噪杂环境都不影响识别」。

## R-025 润色 profile

至少三档可切换的风格（名称 + 力度 + 附加要求），当前档持久化在 `profiles.toml`；切换下一条录音生效；
附加要求只能叠加在通用润色底线规则之后，不能让用户配置改掉「不改意思 / 不回答内容中的问题 / 不翻译」。

## R-026 润色档快捷键槽

最多 3 档可以绑全局快捷键直接切换；只接受带修饰键的组合（避免与「按住说话」的单键冲突）；
注册失败/格式不对要在设置页与状态栏给中文原因，不能静默失效。

## R-027 延时可测

「松手→出文本」的耗时必须被记录且可汇总：设置页显示 p50/p95，`--bench` 能直接判定是否满足 p95 ≤ 1500ms。

## R-028 部分成功可单段重试

- 长听写中若某段识别失败，其余部分照常上屏（已有 `partial_result`）。
- 菜单出现「重识别失败的段」，列出失败段号；点某一段只重跑那一段（不重跑整段、不需要用户重说）。
- 重试结果**只写剪贴板**并提示，不自动注入。
- 重试过程中退出程序不能崩（退出前最多等 5s 让重试线程收尾）。

## R-029 浮层出现在当前工作屏

- 多显示器时，录音浮层必须出现在「光标所在屏」，光标不在任何屏（极少见）时退到前台窗口所在屏，再退到主屏。
- 浮层水平居中、贴在可用区域底部（Dock 上方 88pt），不得越出该屏可用区域。

## R-030 连按不误伤、双击能取回

- 短按（<200ms）一下后 400ms 内再按 = 取回上次结果到剪贴板，不发新上屏、不自动注入。
- 只短按一下就松开：仍要给出失败原因（太短/没声音），不能被双击逻辑吞掉。
- 按住超过 200ms 的正常录音不受影响（没有额外延迟）。

## R-031 录音时长可见

- 录音超过 3 秒后，浮层状态行显示「在听… Ns」，让用户知道程序还在收（不是卡住）。
- 前 3 秒不显示秒数；识别中/上屏中阶段不显示（避免和「识别中…」抢位置）。

## R-032 诊断要能自证

- `--diagnose` 必须能读出：引擎/模型就绪与否、设备、开关集合、常驻内存、最近延迟分位数。
- 诊断不得泄露 API Key 或历史文本。

## R-033 句末标点

- 中文听写结果若以文字结尾且长度 ≥6，自动补「。」；已有标点、英文/代码、短词不动。
- 不做段间逗号（理由见 D-046 / I-031）。

## R-034 学到的改法跨重启保留

- 自动学到的「常被改成的写法」候选要落盘（`suggestions.json`，0600），重启后仍可在设置页采纳/忽略。
- 采纳后写进热词表；忽略后不再出现；已在热词表里的不再重复当候选。

## R-035 上屏失败不吞字

- 粘贴后无法确认文字已落到输入框时，必须把文本留在剪贴板，并提示可从菜单取回。
- 确认上屏后才还原用户原来的剪贴板内容（且仅在期间没人动过剪贴板时）。

## R-036 只录我的声音（声纹门控）

- 设置页「音频」可选开启；开启后低于阈值的段被跳过，不上屏、不进历史。
- 声纹注册/删除都在本地完成，声纹文件 0600 且不上传；阈值默认 0.62。
- 算不出声纹时不得丢弃音频；一段里多数段被跳过时要重跑不过滤的识别并告知用户。

## R-037 标点（可选）

- 装了标点模型（65MB）时可对转写结果补逗号/句号；未装则退化为「句末补句号」。
- 设置页可关；`--diagnose` 显示是否装了模型。

## R-038 自动化测试不污染用户数据

- `--self-test` / `--decode-wav` / `--soak` / `--bench` / `--mic-test` 等 CLI 路径不得写历史、不得落 pending、不得写失败音频。
- 冒烟脚本每次跑完要验证历史条目数不变（第 2c 项）。

## R-039 历史可搜

- 历史页顶部有搜索框，按文字或应用名过滤；无匹配时给明确空态。

## R-040 全链路可自动验证

- 提供 `--simulate <16k wav>`：合成热键按下/松开 + 用 WAV 代替麦克风，走完整链路（浮层、准流式、VAD、识别、标点、上屏请求）。
- 该路径必须 `dryRun` 注入、`testMode` 不写历史。

## R-041 长听写延迟不随时长线性增长

- 连续说话 76s，松手→出字 ≤1500ms（冒烟第 3e 项用 `ERYU_SIM_SPEED=4` 加速喂样本验证）。
- 手段：录音期渐进封口（D-059），松手只解尾巴；超过会话上限先按上限结束。

## R-042 引擎分工要说清楚，不让用户猜

- 设置页引擎分页必须写明两种引擎的取舍（准度差异与代价），并且**换引擎下次录音生效**。
- 默认必须是「一直顺」的那档；「最准」那档由用户主动选。
- `--diagnose` 要能看出当前引擎与两个模型是否就绪。

## R-043 睡眠与切用户不能留下幽灵录音

- 系统睡眠/切换用户时，正在进行的录音必须收尾并提示；唤醒后热键必须是可用的（否则提示如何恢复）。
- 自测命令 `--sleep-test` 必须常绿，且能看出「收尾」与「重挂」两件事都发生了。

## R-044 降噪要真的能用，也要能看出有没有装

- 降噪默认开，依赖 `~/.eryu/models/gtcrn_simple.onnx`；模型缺失时**不静默假装开了**：
  设置页显示「降噪模型还没装」+ 一键下载，`--diagnose` 显示「开（但模型没装，实际不降噪）」。
- 降噪必须在采集链上（重采样之后 16k）实时做，不能等松手才做。

## R-045 音源锁定（实验）要能关、也要能说清代价

- 默认关；开启后每组录音只留「最先说话的那个人」的段，跳过其它段。
- 必须能在设置里一句话说明：两人同时说话分不开；连续 8s 不像会自动解锁。
- 锁错人不能吞掉用户自己的话：解锁条件（≥8s 且 ≥2 段）要保证第二段就能翻转。

## R-046 准确性/延迟必须有可复现的基线

- 仓库内提供语料定义（`bench/refs.json`）与两条脚本：生成语料（`scripts/make-corpus.py`）、跑基准（`scripts/bench.py`）。
- 基准必须走产品链路（`--decode-wav`），不能再用「例子脚本」的数字代替产品表现。

## R-047 轻声也要能输入，且不能把「麦克风没声音」误报成「你按太快」

- 峰值低到 1% 量级的说话声必须能识别（自动增益后送 ASR）。
- 被静音/无输入的麦克风必须继续报「没收到声音」，不能因为放大噪声而假装成功。

## R-048 一条命令完成「真实按键」验收

- `Eryu --acceptance`：打印权限、按键、浮层、流式、结果、延迟六项，写 JSON 报告，退出码表示整体通过与否。
- 验收过程不许向任何应用注入文本（只观察）。
- 20 秒内没有按键也要给出报告（说明是按键没被接住，而不是空跑）。

## R-049 交付要能装一次就跑起来

- `scripts/dist.sh` 产出可直接拖进「应用程序」的 zip；签名在 dist 副本里仍然有效。
- 首次启动若缺模型，必须主动问一次并说明体积（不能等用户按热键才报「模型未安装」）。

## R-050 宁可不上屏，也不要上屏一句幻觉

- 峰值 <2% 的录音一律判为「声音太小」，不上屏、不写历史，提示靠近麦克风或调高输入音量。
- 区分「完全没声音」（归因麦克风/设备）与「有声音但太轻」（归因音量/距离）两种文案。

## R-051 录音中可以一键放弃

- 录音（含 starting）期间按 Esc：取消本次会话，不上屏、不写历史、不落盘。
- 不在录音期间不监听 Esc（不能影响用户正常打字）。
- 浮层要提示这个能力存在（「松开上屏 · Esc 取消」）。

## R-052 每个失败码都要有文案表

- `docs/ERRORS.md` 是错误码的唯一文案来源（码 → 文案 → 下一步 → 可重试性）。
- 新增错误码必须补表；表里写着「可重试」的，界面上必须有对应的重试入口。

## R-053 关键限制要有脚本化指标

- 接缝完整率：`scripts/seam.py`（默认 8 句 × 中速倍速）。
- 音源锁定命中率：`scripts/sourcelock_metric.py`（A/B 交替，句间 0.9s）。
- 两个脚本都在发版前手跑一次，数字记进 `CHANGELOG` 或 `PROGRESS`。

## R-054 壳契约可执行

- `--contract` 必须能退出码 0 并打印 `CONTRACT OK`，且不写历史、不上屏。
- 任何新平台的壳，第一件事是让这条通过。

## R-055 极端状态必须有可跑矩阵

- `scripts/matrix.sh` 覆盖：缺模型 / 设备不存在 / 配置损坏 / 配置目录不可写。
- 要求：每种状态都要有名字 + 下一步，且不写用户数据、不静默失败。

## R-056 文档一致性必须可自动检查

- `scripts/doccheck.sh` 覆盖 ABI 版本、发布版本号、错误码覆盖、默认值口径、里程碑状态。
- 任何新增错误码/ABI 变更/版本变更，冒烟（第 7 项）会立刻报出来。

## R-057 降噪效果必须用信噪比口径测

- `scripts/denoise_table.py` 以 SNR 混噪声、先离线降噪再解码，输出 CER 对比表。
- 任何"降噪更好/更差"的结论必须来自这张表，不能来自固定倍数混合。

## R-058 FFI 必须扛住坏输入

- 空指针、坏 WAV、坏 JSON、非法 UTF-8、超长文本、残缺模型输入都只能"返回错误 + 原因"，不能崩溃、不能改坏配置。
- `core/tests/fuzz_ffi.rs` 是这条的可执行证据。

## R-059 崩溃/强杀后必须能取回结果

- 结果在上屏确认前落盘（`pending/last_result.txt`），SIGKILL 后重启仍能取回。
- `scripts/crash_recovery.sh` 是端到端证据；自测命令若要用 stub，必须显式 `ERYU_ALLOW_STUB=1`。

## R-060 识别类自测不许在 stub 上假绿

- `--decode-wav` / `--simulate` / `--mic-test` / `--soak` 在引擎未安装时必须失败并提示，除非显式 `ERYU_ALLOW_STUB=1`。

## R-061 上限行为必须可端到端验证

- 167s 语料 → `record_limit` → 只保留前 120s → 延迟 ≤1500ms；`scripts/longcap.sh` 是证据。

## R-062 连续说话不许丢整句

- 无停顿语料下，结果里的句子标记必须是连续前缀；`scripts/nopause.py` + 冒烟第 5d 项守住。

## R-063 上屏失败不许静默丢结果

- 未送达/未确认时必须：写剪贴板 + 明确提示 + 菜单可取回；`scripts/fallback.sh` 是证据。

## R-064 设置改完立刻生效

### R-101 引导强制完成一次上屏（第 3 步）

- 页面左：朗读例句「今天天气不错，我们开始吧」（去标点 11 字）；页面右：识别文本（随 `partial_text` 实时出现）。
- 说话两条路，都走真实录音链路：按住当前热键（默认右 Option）；或按住页面里的话筒按钮。
- 松手后按最终结果判定：
  - 文本 ≥4 个字符；
  - 与例句的**字符多重集合交集 ÷ 例句字数 ≥ 0.5**（标点/空格不计；多说的字不扣分）。
- 未满足：显示具体原因（没听到声音 / 太短 / 识别失败 / 麦克风权限），「下一步」禁用，可重试。
- 满足：右侧标「已成功识别」，「下一步」启用。
- 「稍后再说」：写 `onboarding_done=true`，但 `onboarding_probe_done` 保持 false；下次启动直接从第 3 步回来（0.7→0.8 迁移用户同样适用），直到成功一次。
- 安全边界：探针文本**只在引导页显示**，不调用注入器（不写进用户正在用的窗口）；core 照常收到 `submit_result(ok)` 完成闭环（D-110）。
- CLI 与证据：`--onboarding-step N`（0-4）直达某步；`--onboarding-selftest` 断言判定函数；配 `ERYU_MIC_WAV=<真实 WAV>` 可端到端跑一遍（打印 `ONBOARDING SELFTEST OK 第 3 步出字：…`、退出码 0）；截图 `docs/onboarding-3-probe.png`（未出字、按钮灰）与 `docs/onboarding-3-probe-ok.png`（出字、按钮可用）。

### R-102 引导麦克风页自检（第 2 步）

- 实时电平条（复用设置页 `MeterBar`）；进入页面自动开始、离开/关闭即停（不长期占用麦克风）。
- 设备下拉：来自 `eryu_list_devices`，选中即 `setDevice`；无设备时说明「没有检测到麦克风」。
- 「明显声音」阈值：`rms ≥ 0.01`（core 的 silent 档是 0.003；0.01 ≈ -40 dBFS）。
- 连续 3 秒所有 meter 样本都 < 0.01 → 显示「未检测到明显声音，换个麦克风或靠近一点」；任一样本 ≥ 0.01 立即清除并重新计时。
- 该页不阻塞「下一步」（自检提示，不强制）。
- 证据：`docs/onboarding-2-mic.png`。

### R-103 迷你主窗

- 引导结束后出现；尺寸 170×230，可拖动、不可缩放；此后每次启动按 `[ui] mini_window` 决定是否出现。

### R-137 设置页的输入要「打得进去、也收得下上屏」（0.8.2）

- 任何设置页的文本输入（热词、润色名称/快捷键/附加要求、地址类字段）：连续键入字符不得丢焦点、不得打断中文输入法组合态；列表行在编辑时必须保持同一身份。
- 在本应用自己的窗口里，标准编辑快捷键必须可用：mac ⌘C/⌘V/⌘A/⌘Z、Windows Ctrl+C/Ctrl+V/Ctrl+A/Ctrl+Z。
- 把光标放进本应用自己的输入框、按下听写热键：识别结果要能落到该输入框（等价于一次粘贴），并如实回写历史状态（`inserted`，不能因为「读不到」就记 `pending`）。
- 证据：mac `docs/ISSUES.md` I-174 / I-175；Windows 侧同一组用例见 `docs/win-parity.md`「自家窗口输入」小节。
